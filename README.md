# Fleet DVIR dashboard — local uploads only

For routine tracking, share the [stakeholder guide with filter examples](docs/DVIR_Stakeholder_Guide_Revised.docx).
It covers only the simple report, its dropdown filters, downloads and training
follow-up, without the detailed Backend screens.

The [supervisor user guide](docs/Fleet_DVIR_User_Guide.docx) explains the controls,
table columns, days-off and DVIR-history dropdowns, without-DVIR rules, training,
co-driver coverage, exports and common follow-up situations in plain language.

For sharing with supervisors, use **Simple 15-day report** in the sidebar and
**Download Excel report (5 sheets)**. It uses every TruckMate roster driver (not Samsara
activation) and always covers the 15 dates ending on the selected report date.
The same Excel download button is also directly in the sidebar beneath Get DVIR,
available on every page after upload. It updates with the current file/report date
and keeps its generated bytes in session memory only; Clear/removal discards them.
**PTI training not done** is a separate navigation section for roster drivers whose
training is anything other than DONE. It includes empty/missing values, solo and
co-driver filters, name/TMW-ID/vehicle search, clickable individual profiles and a
CSV download of that list. The five-sheet Excel download remains in the sidebar.
Its five table views / Excel sheets are Solo with DVIR, Solo without DVIR,
Co-driver with DVIR, Co-driver without DVIR, and No PTI in entire file. The first
four divide solo drivers and exact crew groups by dated activity in the selected
15 days. Holiday, training and missing-date cases stay visible with their Status.
The fifth lists all roster drivers with neither own nor linked co-driver evidence
anywhere in the uploaded history, including holiday/training cases. Positive
undated counts prevent a false never-recorded classification. This is not a claim
about lifetime history. Each table also has its own CSV download (search filters
apply to that CSV); the Excel button always includes all five complete sheets.
The report contains names, IDs, vehicles, submission counts, last DVIR, holiday
counts, training and training dates. Co-driver rows show both members and separate
authored counts; either submitting places the group in Co-driver with DVIR.
Extra/unmatched crew names are retained.

Blank holiday information is Not supplied, not a fabricated zero. Last DVIR is
the most recent available inspection on or before the report-ending date.
Vehicle names are supplied report context, not a verified per-inspection mapping.

The Excel download is generated in memory from the current upload, using the
blank styled template in src/resources/stakeholder_report_template.xlsx. Frozen headers,
filters, typed dates/counts and text IDs are retained. The runtime uses Python's
standard XML/ZIP support and does not require Node. The template authoring script
is tools/stakeholder_excel/build.mjs; it uses the bundled artifact spreadsheet tool.

Run `streamlit run app.py` from this project (Windows: `.venv/Scripts/python.exe -m streamlit run app.py`).
Open http://127.0.0.1:8501. Every new session starts with an empty upload screen.

Use **Get DVIR** to open the configured n8n download form, download its JSON,
then choose **Upload DVIR JSON**. **Clear uploaded data** removes the active input.
Replacing a file replaces the dataset. Data is held in session memory only:
there is no API polling, saved-file fallback, SQLite, database backups or separate
training upload. Training status is read from the currently uploaded DVIR JSON. No Refresh/Reload control is used.
Optional settings are PTI_DOWNLOAD_URL and PTI_TIMEZONE (America/Chicago by default).
Set PTI_DOWNLOAD_URL privately in the local ignored .env file, an environment
variable, or Streamlit secrets. There is no production URL in the source code.
Without this setting, Get DVIR is disabled; JSON upload still works.
Old API/database environment settings are ignored by the app.

## Navigation

- Overview: roster totals, with/without own DVIR counts, crew presence, holiday
  availability, daily recording trend, consistency, recency and highest DVIR counts.
- Solo with DVIR: source rows without co-driver information and with direct own
  DVIR evidence. Period/date filters show recent activity without changing category.
- Solo without DVIR: source rows without co-driver information or direct own DVIR
  evidence. Co-driver rows with no own submission stay in Co-driver teams.
- Co-driver teams: source crew grouping, combined counts, each member's own activity,
  heatmap, dates, timestamps and CSVs. Its roster members are excluded from both
  solo lists. Filter own DVIR present/missing inside the crew section.
- Individual driver: own history, missing/holiday calendar, source counts, contacts
  and linked crew. No partner inspection is credited to the selected person.
- Data checks & unmatched: source ambiguities and authors outside the primary roster.
  Linked partners are labeled separately from unmatched authors needing review.

## Actual export identity rules

For an export with CODRIVER_* columns, the unprefixed DVIR block belongs to the
primary Samsara_DriverID. The partner block belongs to CODRIVER_driverID. The
shared driverID and lowercase samsara_driverId may describe the partner after a
join; they must not overwrite the primary inspection owner. SamsaraStatus is
attached only to its explicit account lookup ID. Missing/conflicting values stay
Unknown. Tms_ID establishes primary roster membership, with a namespaced TMS key
when its primary Samsara ID is missing.

Crew grouping uses vehicleName, cogoID_0…2, driverName_0…2 and matched_on. In this
export, matched_on identifies the partner's slot; COGOELD identifies the primary
roster driver's slot. Exact crew ID sets are retained instead of transitive merging.
A third crew member without a verified ID/history is shown as unmapped.
Crew timing is not verified per historical inspection, and overlapping crew
rows must not be summed blindly.

Each block's appended_startTIme/appended_endTime arrays retain inspection order.
Repeated authored UTC timestamp pairs are deduplicated by occurrence, preserving
same-time distinct records within a block. Original Samsara inspection IDs are
not supplied, so timestamp matching is a fallback. Vehicle-name/trailer-ID arrays
are equipment inventories, not date-aligned inspection arrays. Reported vehicle
and trailer counts describe full-file PTI entries; do not replace them with the
lengths of the distinct equipment lists. Dated metrics refer to the selected 7/15
calendar dates, ending on the latest actual inspection date by default.

Regular means 4 of 7 or 8 of 15 recorded dates. For a team, the dates are the union
of its members' dates; each person's own count remains visible. Holiday dates
use appended_status_date and are purple in the heatmap when there is no record.
Actual inspections on holiday dates are retained and marked with an asterisk (*).
Heatmaps use separated cells with counts, weekday/date headers and driver IDs.
Green is recorded, amber is recorded with a data review flag, purple is holiday
without a record, and gray is no recorded DVIR. Heatmap row controls show every
driver on the current table page in groups of 20. Calendar gaps are follow-up
information, not verified missed requirements. No employment/driving status is
inferred from a holiday or a missing inspection.

## Implementation and verification

The active entry point uses src/local_ui.py, src/upload_model.py and
src/local_views.py. Older integration helpers are not imported by the app.
Tests in tests/test_upload_model.py and tests/test_dashboard.py cover the current

## Mutually exclusive source categories

The parser assigns each primary roster driver a source_category before period
calculations or visualization: (1) co-driver information, (2) otherwise direct own
DVIR evidence, (3) otherwise solo without DVIR. Direct evidence is nonempty own
inspection timestamp arrays or positive own vehicle/trailer/totalPTI counts. A
shared driverID, Samsara lookup, or vehicle assignment alone is not DVIR evidence.
Explicit zeros and missing values are preserved. Co-driver priority does not depend
on whether the primary, partner or both submitted. Dates and status filters refine
activity inside a category; they never move a driver into another category.

The three primary-roster sets are disjoint and their counts sum to the roster total.
Linked partners outside the primary roster are details within the co-driver view,
not additional primary category counts. A person may still be inspected through
the individual detail page without creating a second category assignment.

## Training and combined driver review

PTITraining / PTITrainingDate belong to the primary uploaded driver identity.
CODRIVER_PTITraining / CODRIVER_PTITrainingDate, when provided, belong to the explicit
partner ID. Training is never copied from a primary driver to a partner. Explicit
DONE (ignoring case and surrounding spaces) shows Done. Empty, missing, Unknown,
Not, and all other values show Not done. Conflicting values show Not done and a
data-review flag. A date
alone does not establish completion. No training database or separate upload is used.

Overview combines the primary solo and co-driver roster in one filterable driver
list, own-DVIR heatmap and consistency comparison. Training follow-up offers both
Done with no dated own DVIR in the selected period and Done with no own evidence
anywhere in the upload. Positive undated counts remain file evidence. These are
follow-up filters, not proof of a missed required inspection or post-training
noncompliance. They do not require that training precede the selected period.

Co-driver navigation has two tabs: All co-drivers · own DVIR (each linked member once,
including linked partners outside the primary roster) and Inspect by co-driver group
(combined team summaries and individual author details). Own-list filters do not
change team tab filters. Primary roster overview totals exclude external partners.

Main TruckMate roster shows all primary roster drivers with Tms_ID (TruckMate /
TMW ID), both solo and co-driver, by default. Its coverage filters use either the
driver OR a linked co-driver submitting. Follow-up includes neither submitting
in the upload or neither having a dated submission in the selected period. The default Samsara
status is All so unknown account states are retained; Active requires explicit
account status evidence. The list does not create a new source category or change
the non-overlapping category totals. An overview shortcut shows its full-file count.

## Current roster coverage rule

A roster driver is covered if either their own block or a member of an explicitly
linked source crew has DVIR evidence. The follow-up list excludes partner-covered
drivers. In a period, covered dates are the union of own and linked members' dates;
regular coverage is 4/7 or 8/15 dates. Multiple submissions on a day count as one
covered date. Only actual crew ID memberships are used, without transitive grouping.

Main TruckMate roster and combined overview filters (including training follow-up)
use this coverage rule. Individual own-DVIR lists, actual-author heatmaps and own
PTI totals remain separate and clearly labeled. Full-file positive undated counts
are evidence but cannot establish a covered date. Categories remain mutually
exclusive and do not change when a partner supplies coverage. This supersedes the
earlier own-only interpretation of roster follow-up above. Source relationships
are those supplied in the current upload; no historical crew assignments are invented.

## Holiday status across the reporting period

Holiday status now covers all selected 7 or 15 dates, rather than just the ending
date: On holiday all period, Partly on holiday, No holiday dates reported, or
Unknown when holiday evidence is missing. Tables show distinct holiday dates and
their count. Only explicit appended_status_date dates are used; separate date
entries are not expanded into an inferred range. An explicit zero holiday count
or an empty date array establishes no reported dates; missing data remains Unknown.
Holiday is personal and is not copied from a co-driver.

Dates without DVIR or reported holiday counts period dates with neither own/linked
co-driver DVIR coverage nor the driver's own reported holiday. The roster gap
filter excludes fully holiday-covered periods. Missing holiday information still
requires an availability check; gaps do not prove a required inspection was missed.
The separate whole-upload no-DVIR filter is unchanged. Regularity remains 4/7 or
8/15 covered dates and is not recalculated against holiday-adjusted opportunities.

Co-driver member-review no-record filters and training follow-up also use own-or-
partner coverage. The team full-file filter is Either member has DVIR / Neither
member has DVIR; no-DVIR never means only that the primary author did not submit.

## Training dates and no-DVIR follow-up

Training is evaluated against the selected report window, not the computer clock.
Tables and CSV show Training relative to report and the uploaded training date.
Known incomplete training, training after the report end, and training on the
report-ending date are excluded from no-DVIR follow-up. These drivers remain in
the full roster with their training label, without falsifying the uploaded Done
status. Training completed during the period starts date-gap checks the following
calendar day. Before-training/at-training cells are labeled separately in the
heatmap and individual calendar. Actual inspections always remain visible.

No-DVIR coverage still accepts either linked co-driver submitting. Holiday dates
are excluded from gaps after training. Missing/conflicting dates or training
status remain explicitly unknown/review, not assumed future training. Unknowns
remain available for follow-up rather than being silently excluded. Source
categories and recorded inspection totals do not change with training eligibility.
This rule supersedes the earlier training-independent follow-up wording.

Shared driver filters include Training relative to report (before/during/after
period, on report-ending date, not trained, unknown and review states). Its labels
and matching rows follow the selected report-ending date and 7/15-day window.

Click a driver name, Driver ID or Open profile cell in driver/inspection tables
to open the Individual driver page for that exact ID. Existing profile search
filters are cleared for direct navigation. Table sorting and paging are respected;
CSV exports remain data-only and do not include the navigation column.

Training / DVIR follow-up includes Training done · DVIR in file, none in period.
This selects training-eligible Done drivers with uploaded inspection evidence but
zero selected-period coverage (own or linked co-driver in combined views). It
excludes never-recorded drivers, current partner-covered drivers and future
training. Reports/CSV include the latest own/co-driver DVIR date in the file.

The active JSON bytes and filename are retained in session memory across page
redirects, independently of the upload widget. This prevents driver profiles from
losing their input during navigation. Removing the file or Clear uploaded data
clears this session copy; a new session still starts empty. No files are saved.

## Current PTI training labels

Only DONE (case/whitespace insensitive) is Done. Blank, null, missing, Unknown,
Not, and every other value are Not done. The PTI training filter has All, Done,
and Not done, and CSVs use these same labels. Dates are still independent: a
missing training date remains unknown; a date alone does not establish Done.

A source field that is empty/unrecognized is not proof of verified incomplete
training. Such rows are labeled Not done / Training not recorded and remain
available in DVIR follow-up. Explicit incomplete values such as Not, Not done,
No or Pending retain the existing not-trained exclusion. Actual DVIR submissions,
co-driver coverage, holiday status and account status do not change. This rule
supersedes earlier Unknown training-status labels.

## Uploaded safety status

Driver/report/CSV/Excel tables include Safety status (file), and team rows show
Safety by driver (file). Supported primary keys are safetyStatus, safetyStatuses,
appended_safetyStatus, appended_safetyStatuses and safety_status; matching
CODRIVER_ fields belong only to the explicit partner ID. Primary fields never
supply the partner's status. Grouped precedence is Unsafe, Resolved, other
non-safe values, then Safe. The profile also shows every supplied value.

Absent/empty values are Not supplied, never assumed Safe. These grouped values
cover the upload and are not assigned to inspection dates, individual vehicles
or present equipment condition. A submission can be completed and Unsafe; safety
does not change inspection counts or the either-co-driver coverage rule. The last
provided DriverDvirData.json contains no safety-related fields, so its report
shows Not supplied until the export includes these fields.

## Main navigation and Backend

The main sidebar links are Simple 15-day report, PTI training not done and
Overview. All detailed pages remain available together in the Backend expander:
Solo with DVIR, Solo without DVIR, Main TruckMate roster, Co-driver teams,
Individual driver, and Data checks & unmatched. Nothing is removed; profile links
and existing detailed-page URLs keep working. Backend is a navigation group,
not a separate server or a change to data processing.

The simple report and its Excel/CSV downloads now say Days off and Days off by
driver instead of Holiday days. The corresponding status says Day off. These
labels use the same reported dates and counts; no categorization logic changes.

Days off wording is also used in the shared UI tables, filters, individual
calendar, heatmap legend/hover text and overview captions. Internal source field
names and stored holiday flags remain unchanged; display mapping preserves the
same filtering and calculations for already uploaded data.

## Training scope of solo and no-record reports

Solo with DVIR, Solo without DVIR and No PTI in entire file now include only
TruckMate roster drivers whose PTI training status is Done. The detailed Backend
solo lists use the same trained-only scope. Not done, empty and unrecognized
training values are excluded from these reports but remain in PTI training not
done and the underlying full roster. The No PTI sheet additionally requires no
own/linked partner inspection evidence across the whole upload. Co-driver group
membership and either-member coverage are unchanged. Excel and CSV downloads
use the same filters as their tables; sidebar workbook caches include a report
version so existing sessions regenerate after this rule change.

In Simple 15-day report, Solo without DVIR and No PTI in entire file include a
Days off follow-up filter. Has days off means a reported count above zero in the
selected 15 days. Zero or Not supplied is grouped as No days off reported; the
original value stays visible. The entire-file tab defaults to No days off reported.
Solo without DVIR also offers DVIR history: No record in entire file or Has records
in file (older or undated evidence without a dated submission in these 15 days).
Combine both filters for follow-up. CSV uses the visible filtered rows; the Excel
workbook includes all five full tables with the new category columns.
